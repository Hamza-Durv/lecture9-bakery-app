Bakery order desk

A local order manager for the November 23–29, 2026 classroom scenario.

Start the app

  1. Open Terminal in this Lecture 9 folder.
  2. Type python3 app.py and press Return.
  3. Open http://127.0.0.1:8000. Keep Terminal open.

To stop, press Control+C in Terminal. To resume later, run the same command. Your decisions are saved automatically. If the address is already in use, use the app already running there or stop the older bakery process first.

Work through the week

  1. Start on Monday. The Orders & days planner already contains the 13 orders in existing_orders.csv.
  2. Review the inbox. Each message shows its original text, order value and eligibility. Changes show the requested total and revenue difference; cancellations show the matching order value and revenue loss. Unmatched orders show an unavailable value. Values describe the request, even when it is rejected. Accept or reject each request. A change or cancellation only affects an accepted order after you approve it.
  3. Check daily oven hours and revenue. Book a helper before accepting an order that needs the extra capacity. A helper adds four hours and costs $100 for that day.
  4. After deciding all pending messages, click Advance to … to move to the next working day. New messages appear. The button is disabled while messages await a decision or after Sunday. Working days cannot go backward.
  5. Search Orders & days by customer. Orders appear under their pickup day alongside available hours and the helper booking. Turn on Show decided messages or open Decision history to review your choices.

Example: Monday's Okafor request is for Tuesday, so it fails the notice rule. Jasmine's Wednesday request is eligible if capacity is available. Saturday demand may justify booking a helper by Thursday; the baker chooses whether to spend the money.

Fixed business rules and assumptions

  • One product per order. Cupcakes cost $40 per dozen and use 30 oven minutes per dozen. Each cake costs $120 and uses two hours.
  • All baking occurs on the pickup date; pickup is at 5 PM. Base capacity is eight oven hours per day. At most one helper may be booked per date, raising capacity to 12 hours. This follows the helper-capacity rule in the supplied message files.
  • New orders, changes, cancellations and helper bookings require at least two calendar days from the selected working day. Monday can affect Wednesday or later. This is a calendar-day rule, not a rolling 48-hour clock.
  • Notice is checked when the baker makes the decision. Delaying a decision can make a request too late. Resolve the inbox before moving forward. Imported future messages stay hidden until their day.
  • A change or cancellation matches the customer's name and pickup date to exactly one accepted order. An ambiguous or missing match is blocked for review. Rejected changes leave the existing order intact.
  • Capacity includes accepted orders only. Pending requests do not reserve time. Decisions are rechecked by Python immediately before saving. No request is automatically accepted or rejected.
  • The helper booking is a commitment; the app does not cancel bookings or undo decisions. Revenue less helper cost excludes ingredients, wages and other expenses, so it is not profit. No payments or Instagram replies are sent.

Implementation

app.py uses only Python's standard library: http.server for the local web server, sqlite3 for storage, and CSV, regular expressions and HTML utilities to import the supplied fixed-format files. HTML, CSS and JavaScript are served directly from that one Python file. There is no AI, external service, package installation or Node.js.

On first launch, the app imports the CSV and the seven Instagram HTML files exactly once. Each pickup date is stored once in a days table. Orders and helper bookings link to it; the planner groups orders by that date without repeating the date in every row. Daily hours and revenue are calculated from accepted orders. Existing data is upgraded automatically without clearing decisions. The database records orders, messages, helper bookings, the working day and decision history in bakery.db, alongside the app. Restarting preserves decisions and does not duplicate imports. The parser supports the supplied Name / Order / Pickup Date format; it is not a general Instagram integration. Source files are read as data and never executed. Workflow Builder files are neither read nor modified.

The read-only GET /api/state endpoint supplies the dashboard. POST /api/action handles decisions, day advancement and bookings in SQLite transactions. Transactions serialize capacity checks and updates. Only the page and this guide are served as files; the database is not exposed for download. The server binds to this computer's loopback address. This is a single-user classroom app with no login.

Data care and testing

Stop the app before copying bakery.db for a backup. Keep it with the app to preserve your work. To start over, click Reset everything beside the working day and confirm. This permanently clears decisions, helper bookings and history, reimports the starting orders and messages, and returns to Monday November 23. Canceling the confirmation keeps your work. Tests must use a copy of the database in a temporary directory, never the real database. The included test_bakery.py makes that copy automatically; run python3 test_bakery.py after the first launch.
